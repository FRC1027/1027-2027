## 3. JSON Serialization Migration (Jackson Elimination & Avaje JSONB)
* **Jackson Removal:** Completely removed all `com.fasterxml.jackson.*` dependencies. In WPILib 2027 and beyond, Jackson is deprecated/discontinued in favor of high-performance, zero-reflection JSON serialization using `io.avaje:avaje-jsonb`.
* **Build Configuration:**
  ```groovy
  annotationProcessor 'io.avaje:avaje-jsonb-generator:3.14'
  implementation 'io.avaje:avaje-jsonb:3.14'
  ```
* **Model Class Annotations:**
  * Added `@Json` annotation to all configuration records and POJOs: `DeviceJson`, `ModuleJson`, `PIDFPropertiesJson`, `PhysicalPropertiesJson`, `SwerveDriveJson`, `ControllerPropertiesJson`, `PIDFConfig`, etc.
  * Used `@Json.Property("property_name")` for snake_case and custom property mapping.
* **Parser Modernization (`SwerveParser.java`):**
  * **ServiceLoader Limitation with Multiple Root Packages:** When `@Json` models reside across multiple unrelated root packages (e.g. `swervelib.*` and `frc.robot.*`), Avaje's generator cannot compute a common top-level package and places `GeneratedJsonComponent` into Java's unnamed/default package. Under Java's `ServiceLoader` specification, provider classes in the unnamed package are ignored.
  * **Explicit Registration:** To ensure 100% deterministic, reflection-free runtime behavior without relying on SPI classpath discovery across unrelated packages, all generated adapters (`SwerveDriveJsonJsonAdapter`, `ModuleJsonJsonAdapter`, etc.) are explicitly registered on the `Jsonb.builder()`:
    ```java
    Jsonb jsonb = Jsonb.builder()
        .add(SwerveDriveJson.class, SwerveDriveJsonJsonAdapter::new)
        .add(PIDFPropertiesJson.class, PIDFPropertiesJsonJsonAdapter::new)
        ...
        .build();
    ```
  * Deserialization calls updated to `jsonb.type(TargetClass.class).fromJson(file)`.

## 4. WPILib 2027 Package & Subsystem Reorganization
* **Hardware & HAL Relocation:**
  * `edu.wpi.first.hal.*` / `org.wpilib.hal.*` migrated to `org.wpilib.hardware.hal.*`.
  * `SimDevice`, `SimValue`, `HALValue`, and `HAL` moved to `org.wpilib.hardware.hal.*`.
* **Framework & Core Classes:**
  * `RobotBase` relocated from `org.wpilib.RobotBase` to `org.wpilib.framework.RobotBase`.
  * System utilities `Timer` and `DataLogManager` relocated to `org.wpilib.system.*`.
  * Driver station error reporting migrated to `org.wpilib.driverstation.DriverStationErrors.reportWarning(...)` and `DriverStationErrors.reportError(...)`.
  * Match state / enabled queries migrated to `org.wpilib.driverstation.RobotState.isEnabled()`.
  * HAL resource usage reporting modernized from legacy integer enums `HAL.report(kResourceType_*, ...)` to `HAL.reportUsage(String resource, String version)` (e.g. `HAL.reportUsage("YAMS", "1")`).
* **Mathematics & Geometry:**
  * `MathUtil.clamp(...)` replaced by Java 21+ standard `Math.clamp(...)`.
  * Geometry constant `Rotation2d.kZero` renamed to `Rotation2d.ZERO`.
  * `Translation2d.getAngle()` returns `Optional<Rotation2d>` to accurately reflect that zero-length translations have no defined orientation. Fallbacks handled via `.orElse(Rotation2d.ZERO)`.
  * `SwerveModuleVelocity` annotated with `@NoDiscard` — method returns must be captured or explicitly handled.
  * `LinearSystemId` removed in favor of `org.wpilib.math.system.Models.*`:
    * `Models.flywheelFromPhysicalConstants(DCMotor, double j, double gearing)`
    * `Models.singleJointedArmFromPhysicalConstants(DCMotor, double j, double gearing)`
    * `Models.elevatorFromPhysicalConstants(DCMotor, double mass, double drumRadius, double gearing)`
  * `DCMotor` fields modernized to remove Hungarian/verbose unit prefixes:
    * `stallTorque` (formerly `stallTorqueNewtonMeters`)
    * `stallCurrent` (formerly `stallCurrentAmps`)
    * `freeCurrent` (formerly `freeCurrentAmps`)
    * `freeSpeed` (formerly `freeSpeedRadPerSec`)
    * `Kv` (formerly `KvRadPerSecPerVolt`)
    * `Kt` (formerly `KtNMPerAmp`)
    * `nominalVoltage` (formerly `nominalVoltageVolts`)
  * `HALValue` constants stripped of Hungarian `k` prefixes: `BOOLEAN`, `DOUBLE`, `ENUM`, `INT`, `LONG`.

## 8. PathplannerLib 2027 Binary Compatibility Shims
* **Root Cause & Compatibility Breakdown:**
  * PathplannerLib `2027.0.0-alpha-3` (latest available on Ranger Robotics Maven) was compiled against WPILib 2027 Alpha 3.
  * In WPILib 2027 Alpha 7, several breaking binary changes occurred:
    1. `Translation2d.getAngle()` changed return type from `Rotation2d` to `Optional<Rotation2d>`.
    2. Static constants in geometry classes dropped Hungarian `k` prefixes:
       * `Translation2d.kZero` $\rightarrow$ `Translation2d.ZERO`
       * `Rotation2d.kZero` $\rightarrow$ `Rotation2d.ZERO`, `kPi` $\rightarrow$ `PI`, `kCW_90deg` $\rightarrow$ `CW_90DEG`
       * `Pose2d.kZero` $\rightarrow$ `Pose2d.ZERO`
    3. `Pair<A, B>` moved from `org.wpilib.math.util.Pair` to `org.wpilib.util.Pair`.
    4. `Alert` relocated from `org.wpilib.driverstation.Alert` to `org.wpilib.util.Alert`.
* **Standard-Compliant Resolution (JDK 25 Class-File API):**
  * Implemented `tools/GenerateWpiCompatShims.java` using JDK 25 standard `java.lang.classfile.*` (zero external dependencies).
  * Injects bridge methods and field aliases directly into `Translation2d.class`, `Rotation2d.class`, and `Pose2d.class`:
    * `public Rotation2d getAngle() { return getAngle().orElse(Rotation2d.ZERO); }`
    * Field aliases: `kZero`, `kPi`, `kCW_90deg`.
  * Added source-level bridge classes:
    * `src/main/java/org/wpilib/math/util/Pair.java` delegating to `org.wpilib.util.Pair`.
    * `src/main/java/org/wpilib/driverstation/Alert.java` delegating to `org.wpilib.util.Alert`.
* **Automated Gradle Pipeline:**
  * Added `generateWpiCompatShims` task to `build.gradle` (executed automatically after `compileJava` and before `classes` / `jar`).
  * `jar.duplicatesStrategy = DuplicatesStrategy.EXCLUDE` ensures clean artifact generation.
